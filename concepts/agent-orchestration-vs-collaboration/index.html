Concept

Agent orchestration is not the same as Human-Agent Collaboration.

Orchestration answers how work should be decomposed, routed, sequenced, retried, or parallelized. Human-Agent Collaboration answers who is participating, what context is visible, what the user approved, what remains local, and how the durable conversation stays coherent across agents.

They compose

A collaboration client can contain orchestration without being reduced to it.

LicoUp’s Adaptive Flywheel is an example of an orchestration-oriented capability inside a broader conversation product. It can model immutable graph revisions, route selection, bindings, authorization, and run reduction.

The Canonical Conversation remains a different authority: it owns the durable human-facing conversation, memberships, structured events, and private runtime bindings. A workflow can run inside that conversation without becoming the conversation itself.

Why the distinction matters

Without it, infrastructure starts pretending to be product authority.

If the orchestration engine, model provider, agent runtime, or relay becomes the implicit owner of identity, conversation history, approvals, and trust, the user-facing boundary becomes difficult to reason about.

A Human-Agent Collaboration Client keeps those responsibilities explicit. It can invoke orchestration, adapters, models, and protocols while still making the conversation and endpoint authority visible to the user.

Protocols are another layer

MCP, ACP, and Lico Arc do not replace the collaboration client.

MCP

MCP can expose tools and context to an agent. That does not by itself define the complete human-facing conversation, participant, or approval model.

ACP

ACP can provide a structured agent-client process boundary. A collaboration client still has to decide how that agent appears in the durable product experience.

Lico Arc

Lico Arc is LicoLand’s separate protocol authority for stable endpoint wire semantics and federation governance. It is not the LicoUp UI or conversation product.

Orchestration graphs

A graph can encode execution strategy. The client still needs to preserve membership, context, approvals, and visible lifecycle evidence around the run.

Current LicoUp boundary

The product already separates conversation and workflow authority in source.

The current LicoUp status records the Canonical Conversation backend and Assistant workflow/Subagent MCP capabilities as implemented in source. That is an implementation claim, not a blanket release or support claim.

Federation, human messaging, recovery, notary, and multi-device history remain planned. The complete Lico Arc endpoint Protocol Line is not implemented today.
