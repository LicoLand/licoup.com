Why this matters

A multi-agent client should normalize without losing semantics.

One agent may emit structured lifecycle evidence, another may stream JSON, another may expose ACP, and another may own a loopback HTTP server. Those differences carry useful information about resume, streaming, replay, cancellation, steering, and runtime identity.

A collaboration client needs an internal contract that can preserve those semantics while still presenting one visible conversation to the user.

LicoUp’s generated inventory explicitly models these interface families so heterogeneous agents can converge on a coherent human-facing experience.

The collaboration layer

When one developer uses several agents, session management becomes a shared-work problem.

As individual coding agents become more capable at planning, editing, running tools, delegating, and managing their own sessions, the value of a layer above them increases.

The human still needs a coherent answer to questions such as: Which agent is participating in this conversation? Which context did it receive? Is this a continuation or a new session? Which agent produced this evidence? What is allowed to leave the endpoint? Which effect was approved? How does the conversation persist if the underlying runtime changes?

Those are Human-Agent Collaboration Client questions.
