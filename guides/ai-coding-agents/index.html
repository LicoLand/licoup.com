Agent coding guide

Claude Code, Codex, Cursor, Copilot, and OpenCode do not expose the same interface.

That is exactly why a Human-Agent Collaboration Client is a separate product layer. The client should preserve each agent’s native semantics while giving the human one coherent conversation, approval, and lifecycle surface.

LicoUp readiness: the current generated compatibility matrix contains adapter targets for all five products on this page, but every one of these target rows is currently unverified with Send enabled = no. This page describes representative interfaces and architecture targets, not released LicoUp compatibility.

Why this matters

A multi-agent client cannot normalize by deleting semantics.

If one agent emits structured lifecycle evidence, another streams JSON, another exposes ACP, and another owns a loopback HTTP server, pretending they are identical makes the client less trustworthy.

A collaboration client instead needs an internal contract that can preserve exact resume behavior, streaming, ordered replay, native lifecycle evidence, cancellation/steering semantics, and private runtime bindings while still presenting one visible conversation to the user.

LicoUp’s generated inventory explicitly models these differences. The long-term goal is not to flatten every agent into one generic subprocess; it is to make heterogeneous agents usable through one coherent human-facing authority model.

The missing layer

When one developer uses several agents, session management becomes a collaboration problem.

Individual coding agents are increasingly capable of planning, editing, running tools, delegating, and managing their own sessions. Those capabilities do not eliminate the need for a user-facing layer above them.

The human still needs to answer questions such as: Which agent is participating in this conversation? Which context did it receive? Is this a continuation or a new session? Which agent produced this evidence? What is allowed to leave the endpoint? Which effect was approved? How do I preserve the conversation if I change the underlying runtime?

Those are Human-Agent Collaboration Client questions, not model-quality questions.
