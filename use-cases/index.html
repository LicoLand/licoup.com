Use cases

Agent collaboration without collapsing every boundary into the cloud.

LicoUp is most useful when you want a conversation-oriented client that can work with local agent runtimes today and evolve toward peer collaboration without giving transport infrastructure endpoint authority.

Current source capability

Talk to local and explicitly configured AI agents.

Use LicoUp as a local-agent client when different agent runtimes already exist on your machine and you want one visible conversation experience around them. Agent discovery is designed to respect the command resolution behavior of the user’s configured shell environment rather than blindly scanning the filesystem.

Good fit: developers using local coding agents, CLI agents, or explicitly configured runtimes who want a client layer without making federation a prerequisite.

Current source capability

Coordinate assistant and subagent workflows inside a conversation.

The Canonical Conversation backend and Assistant workflow/Subagent MCP surfaces provide a durable host for conversation membership, assistant designation, workflow execution, inspection, cancellation, and exact runtime bindings.

Good fit: agent-coding workflows where the user wants multiple roles or temporary subagent execution to remain tied to an inspectable conversation authority.

Preview / evolving

Experiment with protected peer collaboration across endpoints.

Current source includes preview endpoint protection and a candidate Lico Arc outer-envelope adapter. This demonstrates the endpoint-versus-station trust partition, but it is not yet a stable federated product capability or a Published Lico Arc endpoint Protocol Line.

Good fit today: source-level evaluation and architecture experimentation, not a promise of stable cross-device interoperability.

Long-term direction

Federated human–agent collaboration across independently controlled endpoints.

The durable product destination is a conversation experience where humans and visible agents can collaborate across endpoints while each endpoint retains its own keys, plaintext, protected state, approval, and local trust decisions.

Not a current claim: federation, human messaging, multi-device history, recovery, notary, and an official network remain planned until independently implemented and verified.

Where LicoUp differs

Conversation and authority first.

Many agent systems are primarily orchestration frameworks or hosted control planes. LicoUp’s product center is the user-facing conversation and its authority boundaries: who participates, what context is visible, which agent or external capability is admitted, what may leave the endpoint, and which local effect is approved.

That makes LicoUp complementary to agent runtimes and orchestration techniques rather than an attempt to replace every model provider, agent protocol, or execution environment.
